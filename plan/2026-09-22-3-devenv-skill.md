# Plan: Source-maintained devenv skill

## Approved decisions

Add the portable `devenv-project` skill beside `nix-language`, using the existing
package and updater pattern. Keep the Nix command interface and generated bytes
unchanged. Use Python's standard library and a focused devenv helper; do not
introduce a plugin framework, general MDX parser, website build, or model service.

The package contains `SKILL.md`, `references/configuration.md`,
`references/workflows.md`, `references/options.md`, `sources.json`, and upstream's
Apache-2.0 `LICENSE`. Preserve applicable notices and attribute modified excerpts.
Keep this licensing separate from Nix's `COPYING`.

Start from `cachix/devenv` release `v2.3.1`, commit
`2418e1b43797c44de5166176622c8d8fa0149871`. Reverify release metadata and tag
resolution before implementation; reject a moved tag. Future updates select the
latest non-draft, non-prerelease GitHub Release, resolve its full SHA, and support
explicit release selection and regeneration from the recorded pin. Never track
unreleased `main` automatically.

The manifest records release/version/revision, upstream origin, exact curated
paths/headings/options, input/output hashes, and coverage source hashes. Keep
ordering deterministic and exclude timestamps, personal paths, and credentials.
Selection changes require review; missing, renamed, or ambiguous sources fail.

The entrypoint is short, normally discoverable, and routes to relevant references.
It supports creation, explanation, editing, review, and debugging of project
configuration, packages/languages, inputs/imports/profiles, locks, scripts/tasks,
tests, services/processes, and activation. Review upstream's setup skill as
guidance and attribution; updates to it are review signals, never replacements
for authored instructions. No Nix skill installation or agent-specific runtime
is required. Do not overwrite the owner's installed `devenv` skill.

Guidance must inspect existing configuration and locks, distinguish CLI/modules/
nixpkgs versions, check `require_version`, verify version-sensitive options, and
retain local overrides and conventions. Keep project tools in project config;
host installation follows local policy, without personal Nixarchy commands.
Explain deliberate lock updates and preserve resulting locks rather than deleting
them to hide errors. Distinguish native hook and direnv activation/trust. Do not
silently grant trust, edit startup files, run unknown hooks, or start services
just to inspect a project. Respect existing authorization. Explain evaluation,
shell, task, and test side effects, including configured process startup; never
commit secrets or treat documentation snippets as execution authorization.

## Steps

1. **Establish the baseline and source selection.** Read existing updater,
   validator, tests, workflows, README, and Nix package before editing. Run the
   existing checks and record the base commit and Nix package hashes. Reverify
   the agreed devenv release and inspect the exact pinned documentation, option
   data, declarations, generators, templates, license, and upstream setup skill.
   Select exact headings and option keys from these sources, not from memory.
   Verify: baseline passes, tag resolves to the agreed SHA, and every selected
   source exists with unambiguous headings/keys.

2. **Implement focused generation in `scripts/devenv.py`.** Select useful sections
   from release paths: `basics.md`, `files-and-variables.md`, `inputs.md`,
   `pinning.md`, `packages.md`, `composing-using-imports.md`, `profiles.md`, and
   `reference/yaml-options.md` for configuration; `auto-activation.mdx`,
   `integrations/direnv.mdx`, `scripts.md`, `tasks.md`, `processes.md`, `tests.md`,
   and focused `git-hooks.md` guidance for workflows. Render selected
   `docs/src/data/options.json` records and compact pinned language/service
   examples for Python, JavaScript, Rust, Go, and a local service. Include core
   environment/package/shell/test/script/task/process options. Avoid whole-page
   or whole-catalogue mirroring. Add contents lists and full-revision source
   citations. Verify every selected key, default, example, and declaration.

   Convert only explicit supported MD/MDX forms, without evaluating JavaScript,
   Astro, or expressions. Strip frontmatter while retaining title context;
   turn known tabs into labelled sections; preserve admonition nesting and
   warning meaning. Convert release version tips and `small.added-in` notices,
   and support tested `VersionCompatibility` forms when selected. Preserve
   applicable page/ancestor notices when extracting subsections. Preserve fenced
   code, interpolation, and meaningful indentation; normalize common wrapper
   indentation only as needed and retain file-title labels. Reject unknown
   components/imports/expressions/directives, malformed wrappers, and ambiguous
   selections or links. Verify these properties with focused unit fixtures.

   Map documentation links to bundled targets or `https://devenv.sh/`; disclose
   that live-site links are supplementary and may move. Validate package links
   and anchors. Pin devenv declaration links only after checking their paths at
   the recorded SHA; preserve foreign declarations' origin and disclose moving
   links. Render option descriptions, types, defaults, examples, and literal Nix
   expressions without evaluation. Record committed options data and relevant
   generator/template hashes, including `docs/gen/devenv.nix` and selected
   `docs/src/individual-docs` templates. Attribute generated YAML/language pages
   consistently. Do not claim the committed data was freshly rebuilt.

3. **Extend `scripts/update.py` and `scripts/check.py`.** Add explicit
   `--skill nix-language|devenv-project`, defaulting to existing Nix behavior.
   Reuse hashing, JSON, subprocess, link, staging/restoration, and boundary logic
   where semantics match; extract only genuinely shared small helpers. Keep
   identities, upstreams, allowed files, and branches trusted and explicit.
   Stage and validate the complete candidate before replacement; restore original
   bytes on ordinary partial failures. Document that this is not power-loss
   atomic. Automatic changes are limited to the target's references, provenance,
   and necessary notices; reject instruction/selection/code/workflow/test or
   sibling-package changes. Produce deterministic old/new version and revision
   reports, selected source/option changes, coverage changes, and upstream setup
   skill change signals. Verify no-op behavior, moved-tag rejection, immutable
   selections, rollback, and cross-skill isolation in temporary repositories.

4. **Create the package and runtime checks.** Write the concise authored
   `skills/devenv-project/SKILL.md` with the approved guidance, then generate its
   references, manifest, and license from the selected pin. Validate frontmatter,
   references, hashes, notices, and exact package membership. Use the available
   skill-creator validator as a supplementary local check, without depending on
   a personal installation in CI.

   Track a small controlled fixture and reproducible input pins under
   `tests/devenv/`, with a minimal runner if required. Obtain the CLI through the
   pinned upstream build definition and verify its version; use matching modules
   and recorded auxiliary inputs, never the host CLI or moving defaults. For a
   candidate release, materialize its exact module revision in a disposable
   fixture copy and verify resolved inputs; do not let automatic updates edit
   reviewed tests or silently refresh unrelated inputs. Evaluate representative
   option values against the committed data; disagreement fails for investigation.
   Run harmless shell/script/task/`enterTest` assertions with expected output.
   Evaluate language/service settings without launching real services. Never run
   `devenv allow`, change user trust, or evaluate personal projects as fixtures.
   A full upstream docs rebuild requires a demonstrated mismatch and plan revision.

5. **Extend existing workflows and README.** Cover both skills in
   `.github/workflows/check.yml` and `update.yml`, retaining the existing weekly
   schedule and Nix branch. Use distinct per-skill artifacts, concurrency, PRs,
   and branches (`automation/devenv-reference-update` for devenv); maintain at
   most one open PR per skill and no-op when unchanged. Keep generation and
   normal checks read-only, with separate narrowly scoped publication using
   trusted validation code. Reject stale-base artifacts, disallowed members,
   traversal, symlinks, selection changes, and cross-skill mutations. Retain
   full-SHA Action pins, existing workflow-token permissions, manual check
   dispatch for token-created PRs, and no automatic merge or installation.
   Add no credentials. Update README with both skills, per-skill maintenance
   commands, provenance, commit-pinned installation, rollback, and the distinction
   from local `devenv` and upstream `devenv-setup`. Verify with `actionlint` and
   temporary unchanged/changed update runs, including artifact boundaries.

6. **Verify and present the implementation PR.** Run all tests below, regenerate
   devenv twice without a diff, and verify that Nix generated bytes remain exactly
   the baseline. Run clean-runner CI for both skills. Walk through setup, lock
   updates, activation troubleshooting, and version mismatch requests; record
   actual observations separately from executed validation. Do not claim native
   agent discovery or other agents were tested unless actually run. Open the PR
   with `Closes #3`, links to intent/spec/plan, validation evidence, and material
   limits. Keep deviations in this plan in the same commit as their implementation.
   After an authorized merge, run the live updater and distinguish a successful
   no-op from an exercised changed-source publication path.

## Tests

Run from the repository root; any added runtime runner must be invoked by the
devenv validation path and CI so its checks cannot silently be skipped.

```sh
python3 -m unittest discover -s tests -p 'test_*.py'
python3 scripts/check.py
python3 scripts/update.py --check
python3 scripts/check.py --skill devenv-project
python3 scripts/update.py --skill devenv-project --check
python3 scripts/update.py --skill devenv-project --check
actionlint
git diff --check
```

Expected: all commands pass; repeated regeneration changes no files. Compare
`skills/nix-language/` against the recorded pre-implementation base with
`git diff --exit-code <base-commit> -- skills/nix-language`.

Focused tests must cover labelled tabs, each supported version/admonition form,
inherited notices, frontmatter, exact executable code preservation, malformed or
unknown MDX, missing options/sections, deterministic rendering, moved tags,
staging failure, restoration after a partial replacement, and attempted selection
or sibling mutations. Temporary repository tests cover changed and unchanged
updates, per-skill reports, and publication boundaries. Structural checks cover
links/anchors, pinned source/declaration paths, hashes, licensing, and allowlists.
Runtime checks assert actual representative values and harmless command output.
Clean CI must pass for both skills before presenting the implementation PR.

## Rollback

Before merge, revert the implementation commits on the task branch and rerun
the existing Nix checks. After merge, use a reviewed revert PR for the implementation
and workflow changes; retain the approval history. Pause the devenv update path
if needed while preserving the Nix schedule. Restore consumers by reinstalling
the last known-good commit-pinned package. No host configuration, installed skill,
trust settings, or secrets should require restoration because this change does
not modify them.
