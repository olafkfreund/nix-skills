# Plan: wiki-style documentation site on GitHub Pages

## Approved decisions

These come from the approved spec. The plan can be followed without opening
the intent or spec.

**Site and address.**
- mdBook 0.5.4 from the pinned nixpkgs input.
- Sources in `docs/`, published at
  `https://olafkfreund.github.io/nix-skills/` with no custom domain.
- `book.toml`: title "nix-skills", `src = "src"`, `site-url =
  "/nix-skills/"`, search enabled.

**README.** Unchanged apart from one line under the title linking to the
site. Trimming it is a follow-up issue, opened at merge.

**Pages.** `docs/src/`:
- `SUMMARY.md` has four groups: Tutorials, How-to guides, Reference and
  Explanation.
- `index.md`
- `tutorials/getting-started.md`
- `how-to/install.md`, `how-to/update-and-rollback.md`,
  `how-to/fix-discovery.md`, `how-to/contribute.md` and
  `how-to/update-token.md`
- `reference/nix-style.md`
- `explanation/why-skills.md`, `explanation/authored-and-generated.md`,
  `explanation/updates.md` and `explanation/security.md`

**Generated pages,** built at build time and never committed:
`reference/catalog.md`, `reference/options.md` and
`reference/update-schedule.md`.

**Content.**
- It comes from reviewed text: the README sections, CONTRIBUTING, and the
  approved intents and specs of #37, #41, #43, #48 and #54, rewritten per
  page.
- Links to repository files use absolute
  `https://github.com/olafkfreund/nix-skills/blob/main/…` URLs.
- Pages obey the Nix style rules.

**`scripts/docs_catalog.py <root> <out>`** is pure and offline.
- **`catalog.md`:** one row per `skills.json` name, showing:
  - the name, linked to its `SKILL.md` on GitHub;
  - the frontmatter description;
  - the kind: "generated from upstream" when `sources.json` exists,
    otherwise "hand-written";
  - the upstream source and snapshot from `sources.json`, or "—" when
    absent;
  - the licence file (`LICENSE` or `COPYING`), or "repository licence".
- **`update-schedule.md`:**
  - the weekly skills, from the single `skill: [...]` line of
    `update.yml`'s `generate` matrix, parsed with a regular expression;
  - the other skills, which change only through reviewed PRs;
  - the cron line;
  - a link to `../explanation/updates.md`.
- **Fails loudly** if the matrix line is missing or names a skill not in
  `skills.json`.

**`scripts/check_docs.py <src>`** fails if any of these doesn't hold, for
every `*.md`:
- relative links resolve to existing files;
- `#anchors` resolve, using `check.links` and `check.anchors`;
- `nix_style.findings` is empty;
- every page is listed in `SUMMARY.md`, and every entry exists.

**`nix/docs.nix`** is a `pkgs.runCommand "nix-skills-docs"` with `mdbook` and
`python3`. It:
1. copies `docs/`;
2. runs `docs_catalog.py` into `src/reference/`;
3. writes `src/reference/options.md` from `(pkgs.nixosOptionsDoc { options =
   hm.options.programs.nix-skills; }).optionsCommonMark`, where `hm` is a
   `home-manager.lib.homeManagerConfiguration` of
   `homeManagerModules.default` with a minimal user, the same pattern as
   `nix/checks.nix`;
4. runs `check_docs.py`;
5. runs `mdbook build` into `$out`.

**Flake and registry.**
- `packages.<system>.docs` and `checks.<system>.docs` point to that
  derivation.
- `check_collection.py` reserves the skill name `docs`.

**`.github/workflows/pages.yml`.**
- **Triggers:** `push` to `main` and `workflow_dispatch`.
- **Settings:** `permissions: contents: read`, and
  `concurrency: { group: pages, cancel-in-progress: false }`.
- **Job `build`:**
  - `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1` (v7.0.1),
    with `persist-credentials: false`;
  - `cachix/install-nix-action@13d8dd58da0234aa297dedd986986ccb8e7f3e24`
    (v31.11.1);
  - `nix build .#docs --no-update-lock-file`;
  - `actions/upload-pages-artifact@fc324d3547104276b827a68afc52ff2a11cc49c9`
    (v5.0.0), with `path: result`.
- **Job `deploy`** (`needs: build`):
  - `permissions: pages: write, id-token: write`;
  - `environment: { name: github-pages, url: ${{ steps.deployment.outputs.page_url }} }`;
  - `actions/deploy-pages@368f82528645a54fb793d4d04e342629a3f51346`
    (v5.0.1), with `id: deployment`.
- No secrets, no personal token. PRs never deploy.

**Other edits.**
- **AGENTS.md, "Layout and boundaries":** `flake.nix, nix/` becomes "data
  packages, the documentation site and opt-in Home Manager installation",
  and add a `docs/` line.
- **CONTRIBUTING.md:** one paragraph on the site. Pages live in
  `docs/src/`, `SUMMARY.md` must list them, `nix build .#docs` checks them,
  and the generated reference pages are never edited by hand.

**One-time owner setting.** Pages source set to GitHub Actions:
`gh api -X POST repos/olafkfreund/nix-skills/pages -f build_type=workflow`.
It is run after merge, with the owner's approval.

## Steps

1. **`scripts/docs_catalog.py` and its tests** in `tests/test_docs.py`, using
   a temporary fixture.
   → Verify:
   - a generated skill and a hand-written skill both render;
   - a matrix naming an unknown skill fails;
   - a missing matrix line fails;
   - running the script against the real repository lists all 10 skills and
     8 weekly skills. First inspect each provider's `sources.json` field
     names, and record the fields used in the script's docstring.
2. **`scripts/check_docs.py` and its tests.**
   → Verify:
   - a broken link, a missing anchor, a page not in `SUMMARY.md` and a
     `pkgs."foo-bar"` block each fail;
   - a valid tree passes.
3. **`docs/book.toml`, `docs/src/SUMMARY.md` and the twelve authored pages.**
   → Verify: a run of `docs_catalog.py` into a scratch copy, followed by
   `check_docs.py`, passes. Then read each page once against its sources.
4. **`nix/docs.nix`, the flake wiring and the `docs` reserved name.** Stage
   the new files before evaluating.
   → Verify:
   - `nix build .#docs` succeeds;
   - `result/index.html` exists;
   - the catalog lists 10 skills;
   - the options page names `programs.nix-skills.enable`, `.skills`,
     `.agents` and `.directory`;
   - the negative checks: a temporary broken link, and a temporary
     `pkgs."foo-bar"` in a page, each fail the build, and are reverted.
5. **`.github/workflows/pages.yml`.**
   → Verify: `actionlint` is clean. The workflow-level permission is
   `contents: read`, and only `deploy` has `pages` and `id-token`.
6. **README link, AGENTS.md and CONTRIBUTING.md.**
   → Verify: `check_collection.py` passes.
7. **Full checks.**
   - unit tests;
   - `check_collection.py`;
   - `devenv shell check-fast`;
   - `nix flake check`, which now builds `checks.<system>.docs`;
   - `nix build .#nix-skills --no-link`;
   - the aarch64 `drvPath` evaluation.

   Commit in logical groups, push, and open a PR with `Closes #56`.
   → Verify: CI is green, and the PR is `CLEAN`. Do not merge without
   approval.
8. **After merge** (with approval):
   - enable Pages with the `gh api` call;
   - run or await `pages.yml`;
   - open the follow-up issue to trim the README.

   → Verify: the deploy succeeds, and
   `curl -sI https://olafkfreund.github.io/nix-skills/` returns 200. The
   catalog page and search work.

```sh
python3 scripts/check_collection.py
actionlint

nix flake check
nix build .#nix-skills --no-link
nix eval .#packages.aarch64-linux.nix-skills.drvPath --raw
```

## Rollback

- **Before merge:** close the PR and delete the branch.
- **After merge:** `git revert` the implementation commits, which removes
  `docs/`, the scripts, `nix/docs.nix`, the flake outputs and `pages.yml`.
  Disable Pages with `gh api -X DELETE repos/olafkfreund/nix-skills/pages`.
  No skill or package content changes.
