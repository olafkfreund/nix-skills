# Plan: Nix idioms and best practices from nix.dev

Branch: `feat/25-nix-idioms`, based on `main` 4741134.
Intent: `intent/2026-09-23-25-nix-idioms.md`.
Spec: `spec/2026-09-23-25-nix-idioms.md`.

## Approved decisions

- **D1 `github_docs` options** (opt-in; existing providers byte-identical):
  - `CONFIG["license"]` defaults to `"LICENSE"`. It is the upstream path read
    into the package's `LICENSE` output, and `validate_manifest` expects it
    in `inputs` instead of the literal `"LICENSE"`.
  - `CONFIG["markup"]` is `"markdown"` by default, which is today's
    behaviour, or `"myst"`.
  - The manifest records `license` and `markup` **only when they differ from
    the defaults**, so the manifests of `home-manager`, `microvm-nix` and
    `nix-darwin` are unchanged. `validate_manifest` requires the recorded
    values, or the defaults, to equal `CONFIG`.
  - **Refinement of the spec,** recorded as a deviation: the MyST label index
    files are hashed into a separate `label_inputs` manifest field, not into
    `inputs`, because `inputs` is validated as exactly the selected sources
    plus the licence. `label_inputs` must be present, non-empty and valid
    SHA-256 exactly when `markup == "myst"`.
- **D2 `convert_myst(text, path, labels, upstream, revision)`,** run before
  `pin_links`, and failing closed:
  - ```` ```{code-block} LANG ```` / ```` ```{code-block} ```` become plain
    fences. Option lines after the opening are an error.
  - ```` ```{contributors} ```` becomes `*Authors: A; editors: B*`, from
    `:authors:` and `:editors:`. Other fields are an error.
  - `:{3,}{tip|note|warning|important|caution}` and
    `:{3,}{admonition} TITLE` blocks close at the same colon count, tracked
    on a stack. They become `**Tip**`…`**End tip.**` and
    `**TITLE**`…`**End TITLE.**`. Unclosed or mismatched blocks are an error.
  - `(label)=` becomes `<a id="label"></a>`.
  - ``{term}`X` `` becomes `X`. Any other `{role}`…`` is an error.
  - A link target matching `^[A-Za-z0-9_-]+$` is a MyST label:
    - a label in the same file becomes `#label`;
    - otherwise it becomes
      `https://github.com/NixOS/nix.dev/blob/REV/<defining file>`, looked up
      in an index of `(label)=` across `source/**/*.md`;
    - an unknown or ambiguous label is an error.
  - Any other ```` ```{ ```` or `:{3,}{` directive is an error.
  - Fenced code content is never altered.
- **D3 Provider:** `scripts/nix_best_practices.py` holds the `CONFIG` from the
  spec (skill `nix-best-practices`, upstream `https://github.com/NixOS/nix.dev`,
  branch `master`, `license: "LICENSE.md"`, `markup: "myst"`, and the one
  `best-practices.md` selection item), plus the three wrappers.
- **D4 Registration:** add `nix-best-practices` wherever `nix-darwin` is
  registered:
  - `check.py`: 3 maps plus choices;
  - `update.py`: generated files, choices and dispatch;
  - `artifact.py`;
  - the `check.yml` matrix;
  - the `update.yml` generate matrix, and a publish entry for
    `automation/nix-best-practices-reference-update` (reviewed enrollment);
  - the `devenv.nix` loop and `skills.json`.
- **D5 Package:**
  - `skills/nix-best-practices/` holds the generated `LICENSE`
    (CC-BY-SA-4.0), `references/best-practices.md` and `sources.json`, plus an
    authored `SKILL.md` as specified.
  - The SKILL.md states that the adapted material is CC-BY-SA-4.0 and was
    modified by MyST conversion and link pinning.
  - The initial `sources.json` is seeded at the nix.dev `master` SHA from
    `git ls-remote`, then generated with `update.py --revision`.
- **D6 Pointers and docs:**
  - a `nix-language` SKILL.md pointer line;
  - the `nix-workflow` developer routing row;
  - the README: table, `ln -s`, Codex list, Home Manager example, maintenance
    section, automation branch list, and sources and licensing, noting
    CC-BY-SA-4.0.
- **Stop rule:** stop, revise this plan and ask if any of these happens:
  - an existing `github_docs` provider's package changes bytes;
  - the pinned page uses a MyST form outside D2;
  - a label cannot be resolved uniquely.

```sh
  python3 scripts/check.py --skill "$s"

nix build .#nix-skills --no-link --print-out-paths | xargs -I{} test -f {}/share/nix-skills/nix-best-practices/SKILL.md
git diff --exit-code
```

Expected result: every command exits 0, with no diff under
`skills/home-manager`, `skills/microvm-nix` or `skills/nix-darwin`.

## Rollback

Revert the PR's merge commit, or the individual step commits. The
`github_docs` options default to today's behaviour, so reverting step 1 alone
is safe once the new provider is removed. If a `nix-best-practices` update PR
was opened after merge, close it and delete its automation branch.
