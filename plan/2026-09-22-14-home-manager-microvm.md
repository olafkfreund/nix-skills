# Plan: Home Manager and microvm.nix skills

Implement two independently selectable, source-maintained portable skills in
the existing nix-skills collection. Preserve authored instructions, generate
only approved upstream references and provenance/license files, and extend the
existing scoped update-PR pipeline without adding permissions or installers.

## Steps

1. `scripts/home_manager.py`, `scripts/microvm.py`: add explicit providers for
   the Home Manager `master` branch and microvm.nix `main` branch. Resolve full
   commits, fetch exact sources through the existing Nix path, validate selected
   paths and Markdown fences/links, copy the upstream `LICENSE`, generate
   revision/input/output manifests, produce update reports, and publish through
   the existing atomic staging boundary. → verify with provider unit tests and
   temporary-source generation fixtures.

2. `skills/home-manager/SKILL.md` and `skills/microvm-nix/SKILL.md`: author the
   two concise entrypoints with exactly the collection's required `name` and
   single-line `description` frontmatter. Keep each domain separate and link
   only to references inside its own package. → verify with collection metadata
   checks and link/resource validation.

3. `skills/home-manager/references/`, `skills/microvm-nix/references/`, each
   package `LICENSE` and `sources.json`: generate the approved initial snapshot
   from the selected upstream paths:

   - Home Manager: NixOS flake integration, configuration, dotfiles, modular
     services, and writing modules.
   - microvm.nix: introduction/declaration, declarative deployment, host
     integration/systemd, options, networking, and shares.

   Preserve source citations and fenced examples; record the exact upstream
   revision and hashes. → verify generated bytes match each manifest and the
   package contains no unapproved files.

4. `scripts/update.py`, `scripts/check.py`, and `scripts/artifact.py`: register
   both provider names, generated-file allowlists, provenance validation,
   package boundaries, CLI dispatch, and scoped artifact acceptance. Ensure
   `SKILL.md` remains authored and provider artifacts cannot modify another
   skill. → verify boundary, no-op, malformed-source, and rollback tests.

5. `skills.json`, `devenv.nix`, `.github/workflows/check.yml`,
   `.github/workflows/update.yml`, and `README.md`: register the two sorted
   skill names, include both in provider checks and PR matrices, assign distinct
   scheduled update branches, document installation/maintenance commands, and
   describe their pinned source/licensing model. → verify sorted registration,
   actionlint, README links, and generated workflow matrix consistency.

6. `tests/test_home_manager.py`, `tests/test_microvm.py`, and shared provider
   tests where appropriate: cover full-commit branch resolution, source-path
   confinement, link conversion, fence preservation, missing/unsupported
   documentation failures, license/notice changes, deterministic manifests,
   unchanged revisions, and atomic publish restoration. → verify with the full
   Python test suite.

7. Run the approved validation suite from the repository root and inspect the
   final diff against this plan. → verify with:

   ```sh
   python3 scripts/check_collection.py
   python3 -m unittest discover -s tests -p 'test_*.py'
   actionlint
   python3 scripts/check.py --skill home-manager
   python3 scripts/check.py --skill microvm-nix
   python3 scripts/update.py --skill home-manager --check
   python3 scripts/update.py --skill microvm-nix --check
   nix flake check --no-update-lock-file
   nix build .#nix-skills --no-link --no-update-lock-file
   nix eval .#packages.aarch64-linux.nix-skills.drvPath --raw --no-update-lock-file
   ```

   Also run `devenv shell check-fast` and `devenv shell check-providers` when
   the project environment is available. Report network/cache failures
   separately from offline validation failures.

## Tests

The initial generators must be reproducible against their pinned revisions;
`--check` must produce no diff and must not replace authored `SKILL.md` files.
The collection must contain exactly the sorted registry directories, and the
Nix package outputs must include each complete skill directory and license.
Workflow matrices must pass `actionlint`, and provider artifact acceptance must
reject cross-skill, unexpected, or stale-base artifacts.

## Rollback

Before implementation, retain the approved intent, spec, and plan commits. If
implementation fails review, revert the implementation commits or remove only
the two new skill directories, registry entries, provider dispatch, tests, and
workflow/documentation additions. Do not delete the approved artifacts or
alter existing providers. Restore the prior scheduled matrices and rebuild
checks; no host rebuild, skill installation, or repository-setting change is
part of rollback.
