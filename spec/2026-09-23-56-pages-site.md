# Spec: wiki-style documentation site on GitHub Pages

## Facts

Checked on 2026-09-23.

- **The repository and its flake.**
  - The repository is public, and Pages is not enabled (`GET /pages` →
    404).
  - Flake inputs: `nixpkgs` (pinned `d4bff64`) and `home-manager` (pinned
    `cbcbfa2`, following nixpkgs).
  - `packages.<system>` has one package per skill, plus `nix-skills` and
    `default`, from `nix/packages.nix`. `checks.<system>` come from
    `nix/checks.nix`.
- **Tools at the pinned nixpkgs.**
  - `mdbook` is 0.5.4.
  - `mdbook-linkcheck` **has been removed** ("incompatible with mdbook
    version 0.5.0+").
  - `pkgs.nixosOptionsDoc` is present.
- **Module options can be evaluated.** A Home Manager evaluation of
  `homeManagerModules.default` exposes
  `options.programs.nix-skills.{agents,directory,enable,skills}`. This was
  tested with `home-manager.lib.homeManagerConfiguration`, the same way
  `nix/checks.nix` already evaluates the module.
- **Reusable helpers.**
  - `scripts/check.py` has `links(text)` and `anchors(text)`.
  - `scripts/nix_style.py` has `findings(text)`.
  - `scripts/check_collection.py` reserves the skill names `default` and
    `nix-skills`.
- **CI.**
  - The required check `collection-check` needs exactly `check`,
    `collection` and `distribution` (`scripts/check_jobs.py`).
  - `distribution` runs `nix flake check`, so any new flake check becomes
    part of the required status automatically.
  - All workflow actions are pinned by commit hash.
- **Where the facts live.**
  - `skills.json` holds the skill list.
  - Each skill's `sources.json` holds the upstream source, snapshot and
    outputs. Two skills have none: `nix-workflow` and `nixos-coding-agents`
    are written by hand.
  - `update.yml` lists the auto-updated skills in its `generate` matrix
    line: `skill: [nix-language, …]`, eight entries.

## Design

### Default answers to the intent's open questions

The intent was approved without answers. These defaults apply unless the spec
review changes them:

1. **Address.** The default project site,
   `https://olafkfreund.github.io/nix-skills/`, with no custom domain.
2. **README.** Unchanged in this task, apart from one line at the top
   linking to the site. Trimming it is a follow-up issue, opened when this
   task merges.
3. **Module options.** Generated from the module with `nixosOptionsDoc`.

### Site layout: `docs/`

```
docs/
  book.toml                      # title, src = "src", site-url = "/nix-skills/", search on
  src/
    SUMMARY.md                   # the navigation, grouped under four headings
    index.md                     # what nix-skills is, who it is for, where to start
    tutorials/getting-started.md # install → check → start prompt (adapted from README "Getting started")
    how-to/install.md            # declarative (module + agents table) and manual, per agent
    how-to/update-and-rollback.md
    how-to/fix-discovery.md      # symlinks, OpenCode duplicates, /skills checks
    how-to/contribute.md         # summary, and links to CONTRIBUTING and AGENTS on GitHub
    how-to/update-token.md       # narrowing UPDATE_PR_TOKEN
    reference/nix-style.md       # the two rules, the grammar, the keywords and the marker
    explanation/why-skills.md
    explanation/authored-and-generated.md
    explanation/updates.md       # the pipeline: generate → accept → PR → Check → protected merge
    explanation/security.md      # tokens, permissions, branch protection, sandboxing links
```

Generated at build time, never committed:
- `reference/catalog.md`;
- `reference/options.md`;
- `reference/update-schedule.md`.

`SUMMARY.md` lists them.

Page content comes from existing, reviewed text: the README sections,
CONTRIBUTING, and the approved intents and specs of #37, #41, #43, #48 and
#54. It is rewritten for its page. Links to repository files use absolute
GitHub URLs, because the site is not the repository.

### Generator: `scripts/docs_catalog.py`

A pure, offline script: `docs_catalog.py <repo-root> <out-dir>`.

- **`catalog.md`** has one table row per skill in `skills.json`:
  - the name, linked to its `SKILL.md` on GitHub;
  - the frontmatter `description`;
  - the kind: "generated from upstream" when `sources.json` exists,
    otherwise "hand-written";
  - the upstream source and snapshot from `sources.json`, as the recorded
    URL and revision;
  - the licence file present (`LICENSE` or `COPYING`), or "repository
    licence".
- **`update-schedule.md`:**
  - the skills in `update.yml`'s `generate` matrix, which update weekly,
    parsed from the single `skill: [...]` line with a regular expression, so
    no YAML dependency is needed;
  - the skills not in it, which change only through reviewed PRs;
  - the cron line, quoted from the file;
  - a link to `explanation/updates.md`.
- **Fails loudly** if the matrix line is not found or names a skill that is
  not in `skills.json`, so the page cannot silently go wrong.

The exact `sources.json` fields read (source URL, revision or snapshot) are
confirmed per provider during implementation. Missing fields are shown as
"—", never guessed.

### Build: `nix/docs.nix` → `packages.<system>.docs`, and `checks.<system>.docs`

`pkgs.runCommand "nix-skills-docs"`, with `mdbook` and `python3` as native
build inputs:

1. Copy `docs/` into the build directory.
2. Run `scripts/docs_catalog.py` into `src/reference/`.
3. Write `src/reference/options.md` from
   `(pkgs.nixosOptionsDoc { options = <HM evaluation>.options.programs.nix-skills; }).optionsCommonMark`.
   The evaluation uses the same `home-manager.lib.homeManagerConfiguration`
   pattern as `nix/checks.nix`.
4. **Validate the sources** with a small script,
   `scripts/check_docs.py <src>`. For every Markdown page it checks that:
   - every relative link points to an existing page;
   - every `#anchor` resolves, using `check.links` and `check.anchors`;
   - the page passes `nix_style.findings`;
   - every page is listed in `SUMMARY.md`, and every `SUMMARY.md` entry
     exists.

   Any failure fails the build.
5. `mdbook build` into `$out`.

In the flake:
- `packages.<system>.docs` is built by `nix/docs.nix`;
- `checks.<system>.docs` points to the same derivation, so
  `nix flake check`, and with it the required `distribution` job, builds and
  validates the site on every PR;
- `check_collection.py` reserves the skill name `docs`, so no skill can
  collide with the output.

### Publish: `.github/workflows/pages.yml`

- **Triggers:** `push` to `main`, and `workflow_dispatch`. Workflow-level
  `permissions: contents: read`. `concurrency: { group: pages,
  cancel-in-progress: false }`.
- **Job `build`** (`contents: read`):
  - checkout with `persist-credentials: false`;
  - `cachix/install-nix-action` (the same pinned hash as `check.yml`);
  - `nix build .#docs --no-update-lock-file`;
  - `actions/upload-pages-artifact` with `path: result`, pinned by hash.
- **Job `deploy`** (`needs: build`):
  - `permissions: pages: write, id-token: write`;
  - `environment: github-pages`;
  - `actions/deploy-pages`, pinned by hash.
- There are no secrets and no personal token. PRs never deploy.
- **One-time owner setting:** Settings → Pages → Source → **GitHub
  Actions**. It can also be set with `gh api -X POST
  repos/olafkfreund/nix-skills/pages -f build_type=workflow`, with the
  owner's approval.

### Other edits

- **README.md:** one line under the title linking to the site. No other
  change.
- **AGENTS.md, "Layout and boundaries":**
  - `flake.nix, nix/` becomes "data packages, the documentation site and
    opt-in Home Manager installation";
  - add `docs/` as the site sources, with generated reference pages.
- **CONTRIBUTING.md:** one short paragraph. Site pages live in `docs/src`,
  and `SUMMARY.md` must list them. `nix build .#docs` checks links and
  style. The catalog, options and update schedule are generated, so never
  edit them by hand.
- **Tests:** `tests/test_docs.py`.
  - `docs_catalog` against a temporary fixture:
    - a generated skill and a hand-written skill;
    - a matrix line;
    - a matrix naming an unknown skill, which fails;
    - a missing matrix line, which fails.
  - `check_docs`:
    - a broken link, which fails;
    - a missing anchor, which fails;
    - a page not in `SUMMARY.md`, which fails;
    - a quoted-name violation, which fails;
    - a valid tree, which passes.

## Alternatives rejected

- **MkDocs Material.** It has been in maintenance mode since early 2026,
  with critical fixes only until May 2027. Zensical, its successor, is
  young.
- **Zensical.** It is too new to pin into a build that should stay stable.
  It can be revisited later.
- **Astro Starlight** (devenv's docs tool). It needs an npm dependency tree,
  which is heavier to package reproducibly than a single binary.
- **`nixos-render-docs`**, the Nixpkgs manual toolchain. It is powerful but
  heavy, and built for manuals rather than a wiki.
- **mdbook-linkcheck or linkcheck2.** The first is removed from nixpkgs. The
  second would be a new dependency, when the repository's own link and
  anchor helpers already do this, including within-page anchors.
- **The GitHub wiki feature.** It is not versioned with the code, cannot be
  reviewed under branch protection, and cannot be generated from repository
  data.
- **Committing the generated pages.** They would drift from the data they
  describe, which is the problem this task removes.
- **Deploying from a `gh-pages` branch.** It needs a write token to push the
  branch. Actions-based Pages deployment needs no stored token.

## Risks

- **Duplicated content** between the README and the site until the README
  trim. Mitigated by the follow-up issue, and by the site linking to the
  README as the source for the per-agent table until then.
- **Options rendering** depends on `nixosOptionsDoc` behaviour at the pinned
  nixpkgs. A change there fails the build visibly in CI, not silently.
- **mdBook 0.5.x configuration changes** between nixpkgs bumps. The build
  runs on every PR, so breakage shows before merge.
- **Pages is not enabled** at first deploy: the deploy job fails with a
  clear error until the owner enables it. The build job still passes.
- **Generated catalog fields differ between providers.** Unknown fields show
  "—". The generator tests cover the fields it relies on.

## Verification

- `python3 -m unittest discover -s tests -p 'test_*.py'` passes, including
  `test_docs.py`.
- `nix build .#docs` succeeds offline. The output has `index.html`, the
  generated catalog lists all ten skills, and the options page shows
  `programs.nix-skills.enable`, `.skills`, `.agents` and `.directory`.
- **Negative checks:** a temporary broken link, and a temporary
  `pkgs."foo-bar"` in a page, each make `nix build .#docs` fail. Both are
  reverted.
- `python3 scripts/check_collection.py`, `devenv shell check-fast`,
  `nix flake check` (which now includes `checks.<system>.docs`) and
  `actionlint` pass.
- **After merge, with Pages enabled:** the `pages.yml` run succeeds, and
  `https://olafkfreund.github.io/nix-skills/` serves the index, the catalog
  and search.
