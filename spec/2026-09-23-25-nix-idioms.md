# Spec: Nix idioms and best practices from nix.dev

The intent was approved without answers, so its recommendations apply:

- a new `nix-best-practices` skill;
- `best-practices.md` only;
- MyST converted to portable Markdown, failing closed on anything else.

Reject any of them at this review.

## Facts

Taken from nix.dev `master` at `f962ac731fb7…` on 2026-09-23.

- `source/guides/best-practices.md` is 7,504 bytes. It has seven sections:
  - URLs;
  - `rec` sets;
  - `with` scopes;
  - `<...>` lookup paths;
  - reproducible Nixpkgs configuration;
  - updating nested attribute sets;
  - reproducible source paths.
- The licence is `LICENSE.md`, CC-BY-SA-4.0.
- MyST constructs used, exhaustively:
  - ```` ```{code-block} nix ```` (16 times) and ```` ```{code-block} ```` (once);
  - one ```` ```{contributors} ```` block, with `:authors:` and `:editors:`;
  - admonitions: `:::{tip}` (9), `:::{note}` (1), a titled
    `:::{admonition} NixOS` (1), and one four-colon `::::{tip}` containing a
    nested three-colon admonition;
  - three `(label)=` targets;
  - one role, ``{term}`Nixpkgs` ``;
  - MyST cross-reference links whose target is a label, not a path: two
    `[…](pinning-nixpkgs)`. That label is defined as `(pinning-nixpkgs)=` in
    `source/tutorials/first-steps/towards-reproducibility-pinning-nixpkgs.md`.
- All other links are absolute `https`.
- `github_docs` (`scripts/github_docs.py`) is shared by `home-manager`,
  `microvm-nix` and `nix-darwin`. It hard-codes `read("LICENSE")`, and

  file. That would silently turn `pinning-nixpkgs` into a URL for a file
  that doesn't exist.

## Design

### 1. `github_docs` gains two opt-in config keys

These keys change nothing for existing providers: their outputs must stay
byte-identical.

- **`license`** (default `"LICENSE"`): the upstream licence path read into
  the package's `LICENSE` output.
- **`markup`** (default `"markdown"`, meaning today's behaviour, or
  `"myst"`): with `"myst"`, `convert_myst()` runs before `pin_links`.
  `validate_manifest` checks both keys against `CONFIG`, as it already does
  for the selection.

### 2. `convert_myst(text, labels, upstream, revision)`: fail closed

It processes lines outside fenced code, and treats a MyST directive fence as a
block:

- **Code blocks:** ```` ```{code-block} LANG ```` becomes ```` ```LANG ````,
  and ```` ```{code-block} ```` becomes ```` ``` ````. Directive option lines
  (`:name: value`) directly after the opening are an error, since none are
  used today.
- **Contributors:** the ```` ```{contributors} ```` block becomes one
  attribution line, `*Authors: …; editors: …*`, taken from its `:authors:`
  and `:editors:` fields. CC-BY-SA requires attribution, so it is kept, not
  dropped. Any other field is an error.
- **Admonitions:** `:{3,}{tip|note|warning|important|caution}` and
  `:{3,}{admonition} TITLE` open a block. The block closes at a line with the
  same number of colons, so nesting is tracked by colon count on a stack. The
  output uses the existing nixpkgs convention: `**Tip**` … `**End tip.**`,
  and `**TITLE**` … `**End TITLE.**`. Unclosed or mismatched blocks are an
  error.
- **Targets:** `(label)=` becomes `<a id="label"></a>`.
- **Roles:** ``{term}`X` `` becomes plain `X`. Any other role is an error.
- **Cross-references:** a link target with no scheme, no `/`, no `.` and no
  `#` is a MyST label. It is looked up in `labels`, an index of every
  `(label)=` in `source/**/*.md` of the pinned checkout.
  - It becomes `https://github.com/NixOS/nix.dev/blob/REV/<file>`, the pinned
    source file that defines the label.
  - An unknown or ambiguous label is an error.
  - Label links inside the same file point to the local `<a id>`.
- **Unknown directives:** any other ```` ```{…} ```` or `:::{…}` is an error.

The label index is built from the pinned source that `github_docs` already
fetches. Every file it reads is hashed into `inputs`, for provenance.

### 3. New `nix-best-practices` skill

- **Provider:** `scripts/nix_best_practices.py`, with
  `CONFIG = {skill: "nix-best-practices", upstream: "https://github.com/NixOS/nix.dev", branch: "master", license: "LICENSE.md", markup: "myst", selection: [{source: "source/guides/best-practices.md", output: "references/best-practices.md", title: "Best practices"}]}`
  and the three wrappers, as in `scripts/microvm.py`.
- **Package:** `LICENSE` (the CC-BY-SA-4.0 text from `LICENSE.md`),
  `references/best-practices.md`, `sources.json`, and an authored `SKILL.md`:
  - It triggers when writing or reviewing Nix expressions for style and
    reproducibility.
  - It points to the reference by topic, tells the agent to check the user's
    project conventions first, and notes that nix.dev guidance targets
    current Nix and Nixpkgs.
  - It hands language semantics over to `nix-language`.
  - It states that `references/best-practices.md` is adapted from nix.dev,
    under CC-BY-SA-4.0, and was modified by MyST conversion and link pinning.
- **Registration,** as for nix-darwin:
  - `check.py`: the upstream map, the provider module map, the
    `github_docs` set and choices;
  - `update.py`: generated files, choices, and dispatch rejecting
    `--release`, `--dump` and `--sha256`;
  - `artifact.py`: choices;
  - the `check.yml` matrix;
  - the `update.yml` generate matrix, and a publish entry for
    `automation/nix-best-practices-reference-update`. This is a reviewed
    updater enrollment.
  - the `devenv.nix` loop and `skills.json`;
  - the README: table, links, Codex list, Home Manager example, maintenance
    section, automation branch list, and sources and licensing.
- **Initial snapshot:** seeded `sources.json` at the current nix.dev `master`
  SHA, then `update.py --skill nix-best-practices --revision <SHA>`.

### 4. Pointers

- `skills/nix-language/SKILL.md` (authored) gains one line: for idioms and
  reproducibility practice, use `nix-best-practices` if installed, otherwise
  nix.dev's best practices page.
- `nix-workflow`'s developer routing row names `nix-best-practices`.

## Alternatives rejected

- **A reference inside `nix-language`.** That puts two upstreams, two
  generators and two licences (LGPL-2.1 and CC-BY-SA-4.0) in one package,
  which none of the providers supports.
- **Copying raw MyST.** Agents would see directive syntax as literal text,
  and `pinning-nixpkgs` would become a broken path link.
- **A hand-written map of label URLs.** It would need editing whenever nix.dev
  adds a reference. An index built from the pinned source resolves labels
  automatically, and still fails closed.
- **Linking cross-references to nix.dev's published URLs.** Those are derived
  from the site structure and unpinned. Pinned GitHub source links match the
  rest of the collection.
- **Dropping the contributors block.** CC-BY-SA requires attribution.
- **Adding more nix.dev pages now.** They can be later, reviewed selection
  changes.

## Risks

- **Existing `github_docs` providers must not change:** home-manager,
  microvm-nix and nix-darwin must regenerate byte-identically at their pins.
  This is the main regression check.
- **nix.dev may adopt new MyST constructs.** The weekly update then fails
  closed, and a reviewer extends the converter.
- **Licence obligations:** attribution, licence link, change notice and
  share-alike are covered by the LICENSE file, the per-reference header, the
  contributors line and the SKILL.md statement. The repository does not
  relicense.
- **Hosts:** CI runners and local runs only.
