# Spec: a disposable NixOS demo VM for agentic coding

## Facts

Checked on 2026-09-23.

- **Relative path inputs.** A subflake in `demo/` with
  `inputs.nix-skills.url = "path:..";` evaluates against its parent flake.
  This was tested with Nix 2.34.8. The feature needs Nix 2.26 or newer. When
  run as `github:olafkfreund/nix-skills?dir=demo`, the parent is the same
  fetched revision, so the demo always uses the skills of its own commit.
- **llm-agents.nix packages** (`meta.mainProgram` and licence label):

  | Package | Binary | Licence |
  | --- | --- | --- |
  | `claude-code` | `claude` | unfree |
  | `codex` | `codex` | Apache-2.0 |
  | `opencode` | `opencode` | MIT |
  | `gemini-cli` | `gemini` | Apache-2.0 |

  Their unfree licence is marked `free = true`, so no `allowUnfree` is
  needed.
- **Pins.** The repository's nixpkgs (`d4bff64`) is on the unstable line,
  compatible with llm-agents.nix. `pkgs.testers.runNixOSTest` and
  `home-manager.nixosModules.home-manager` exist at the pinned revisions.
- **Skill directories.** The Home Manager module installs skills into agent
  directories (`nix/agent-directories.nix`): `claude` → `.claude/skills`,
  `codex` → `.agents/skills`, `opencode` → `.config/opencode/skills`,
  `antigravity` → `.gemini/config/skills`. OpenCode also reads
  `.claude/skills` and `.agents/skills`. Gemini CLI has no entry.
- **KVM on GitHub's runners.** Standard Ubuntu runners have `/dev/kvm`
  since January 2024. It needs a udev rule to become usable, and is
  sometimes unavailable.
- **Required CI.** The required check is `collection-check`, which needs
  the `check`, `collection` and `distribution` jobs of `check.yml`.

## Design

### Default answers to the intent's open questions

The intent was approved without answers. These defaults apply unless the spec
review changes them:

1. **Agents.** Claude Code, Codex and OpenCode by default. Gemini CLI is
   available as an option, off by default.
2. **Location.** A `demo/` subflake with its own `flake.lock`. The main
   flake is unchanged, so skill users never lock the demo's inputs.
3. **VM technology.** NixOS's built-in QEMU VM
   (`config.system.build.vm`). microvm.nix can be added later.
4. **CI.** A separate, non-blocking workflow, `demo.yml`. It is not part of
   `collection-check`.
5. **Console only.** Serial console, with automatic login, and SSH on a
   host-local port. No desktop.

### `demo/flake.nix`

- **Inputs:**
  - `nix-skills.url = "path:..";`
  - `nixpkgs.follows = "nix-skills/nixpkgs";`
  - `home-manager.follows = "nix-skills/home-manager";`
  - `llm-agents.url = "github:numtide/llm-agents.nix";` with no `follows`,
    as upstream advises.
- **`nixConfig`:** `extra-substituters = [ "https://cache.numtide.com" ];`
  and the Numtide public key. It is used only when the user accepts flake
  configuration; builds work without it, only slower.
- **Outputs**, for `x86_64-linux` and `aarch64-linux`, with CI covering
  `x86_64-linux` only:
  - `nixosModules.demo = ./demo.nix;`, reusable by the starter template
    (#58);
  - `nixosConfigurations.demo`, built by `nixpkgs.lib.nixosSystem` with
    `home-manager.nixosModules.home-manager`, `./demo.nix`, and
    `specialArgs = { inherit (inputs) nix-skills llm-agents; };`;
  - `packages.<system>.vm` = `nixosConfigurations.demo.config.system.build.vm`,
    and `packages.<system>.default = vm`;
  - `apps.<system>.vm` and `apps.<system>.default`, a program running
    `${vm}/bin/run-nix-skills-demo-vm`, so `nix run …?dir=demo` starts the
    VM;
  - `checks.<system>.vm-test` (see the VM test below).

### `demo/demo.nix` (a NixOS module)

- **The `demo.agents` option:** a list drawn from `claude-code`, `codex`,
  `opencode` and `gemini-cli`. The default is
  `[ "claude-code" "codex" "opencode" ]`.
  - The selected packages come from
    `llm-agents.packages.${pkgs.stdenv.hostPlatform.system}`.
  - Skill directories are set with `programs.nix-skills.agents`:
    - `claude-code` → `"claude"` and `codex` → `"codex"`;
    - `opencode` → `"opencode"`, but only when neither `claude-code` nor
      `codex` is selected, because it reads their directories and would
      otherwise see every skill twice;
    - `gemini-cli` adds no skill directory; the tutorial names this gap.
- **System:**
  - `networking.hostName = "nix-skills-demo"`;
  - `system.stateVersion`;
  - `nix.settings.experimental-features = [ "nix-command" "flakes" ]`, plus
    the Numtide cache and key;
  - `virtualisation.podman.enable = true`;
  - `environment.systemPackages` with the selected agents, `devenv`, `git`
    and `curl`.
- **User `demo`:**
  - `isNormalUser`, in the `wheel` group, with `initialPassword = "demo"`;
  - `services.getty.autoLogin.user = "demo"`;
  - `services.openssh.enable = true`.

  The fixed password is acceptable only because SSH is forwarded to the
  host's loopback address. The tutorial says so.
- **Home Manager for `demo`:**
  - imports `nix-skills.homeManagerModules.default`, with
    `programs.nix-skills = { enable = true; agents = <mapped>; };`;
  - `home.stateVersion`;
  - a sample project at `~/example`: a `README.md` with the start prompt
    and next steps, and a minimal `devenv.nix` and `devenv.yaml`, for
    example Python.
- **VM settings,** under `virtualisation.vmVariant`:
  - `memorySize = 4096`, `cores = 4`, `diskSize = 16384`;
  - `graphics = false`;
  - `forwardPorts`: host `127.0.0.1:2222` to guest port 22.
- **No secrets.** The login, API keys and agent sign-in happen at run time
  inside the VM.

### VM test: `checks.<system>.vm-test`

`pkgs.testers.runNixOSTest`, with node `machine` importing
`home-manager.nixosModules.home-manager` and `./demo.nix`, the same
`specialArgs`, and the default agents. The Python test script:

1. `machine.wait_for_unit("multi-user.target")` and
   `machine.wait_for_unit("home-manager-demo.service")`;
2. for each binary (`claude`, `codex`, `opencode`):
   `machine.succeed("su - demo -c 'timeout 60 <bin> --version'")`;
3. for each of `.claude/skills` and `.agents/skills`: the directory lists
   the same count as `skills.json` (read at evaluation time), and
   `nix-workflow/SKILL.md` is readable;
4. `.config/opencode/skills` does **not** exist, which proves the duplicate
   rule;
5. `podman --version` and `devenv version` succeed, and
   `~/example/README.md` exists.

The test VM has no network, so nothing contacts a model or a registry.

### CI: `.github/workflows/demo.yml` (not a required check)

- **Triggers:**
  - `pull_request` and `push` to `main`, with paths `demo/**`, `nix/**`,
    `skills/**`, `skills.json`, `flake.nix` and `flake.lock`;
  - `schedule` weekly;
  - `workflow_dispatch`.
- **Permissions:** `contents: read`.
- **Job `vm-test`:**
  - checkout with `persist-credentials: false`;
  - install Nix (the pinned action), with `extra-substituters` for Numtide;
  - enable KVM with the udev rule (`KERNEL=="kvm", GROUP="kvm",
    MODE="0666"`, then reload and trigger);
  - run `nix build ./demo#checks.x86_64-linux.vm-test -L
    --no-update-lock-file`, and then `nix build ./demo#vm`.
- **If `/dev/kvm` is missing,** the job fails with a clear message. It is
  not required, so it never blocks merging, but the red result stays
  visible.

### Documentation

- **`docs/src/tutorials/demo-vm.md`** ("Try it in a demo VM"), listed in
  `SUMMARY.md` after Getting started. It covers:
  - the requirements: Linux with KVM, Nix 2.26 or newer with flakes, and
    the RAM, disk and download sizes measured during implementation;
  - `nix run github:olafkfreund/nix-skills?dir=demo`;
  - logging in (automatic on the console, or `ssh -p 2222 demo@127.0.0.1`
    with password `demo`);
  - adding your own key, and signing in to an agent;
  - `cd ~/example`, the start prompt, and checking skills with `/skills`;
  - resetting by deleting `nix-skills-demo.qcow2`;
  - changing the agents in a local clone;
  - what the demo shows and does not show: the Gemini CLI gap, and that
    it is not a hardened sandbox.
- **AGENTS.md** gains a `demo/` layout line: a separate flake and lock,
  with a non-blocking CI.
- **CONTRIBUTING.md** gains one line on the demo lock. `demo/flake.lock` is
  updated deliberately and independently, and lock-only bumps stay exempt
  from intent, spec and plan.

## Alternatives rejected

- **Demo outputs in the main flake.** Every skill user would lock
  llm-agents.nix and its nixpkgs. The intent forbids this.
- **microvm.nix first.** It adds an input and a host-side runner model. The
  built-in VM needs nothing extra, and microvm.nix can follow.
- **Requiring the VM test in branch protection.** Flaky KVM would block
  unrelated pull requests.
- **Choosing agents at `nix run` time.** Flakes cannot take arguments. Users
  edit one list in a clone, and the starter template (#58) handles
  personalisation properly.
- **A graphical desktop.** It would take several more gigabytes and much
  slower boots. No selected agent needs a GUI.
- **Building API keys or secrets into the image.** Forbidden by the intent,
  and unnecessary.
- **Installing `"opencode"` alongside Claude or Codex.** It gives duplicate
  skill names, as the docs already warn.

## Risks

- **Agent `--version` touching the network or hanging** in the offline test
  VM. Mitigated by `timeout 60`. If an agent cannot print its version
  offline, the test checks that the binary is on `PATH` instead, recorded
  as a plan deviation.
- **KVM flakiness on runners** makes the job red but never blocks merging.
  The job is re-run manually.
- **Download size.** Agent binaries and the VM closure are large. Real
  sizes are measured and documented. The Numtide cache reduces local
  builds.
- **Relative path inputs need Nix 2.26 or newer.** Older Nix fails with a
  clear error, and the tutorial states the requirement.
- **llm-agents.nix changes daily.** The demo lock pins it. Bumps are
  deliberate and tested by `demo.yml`.
- **The fixed password `demo`** is safe only because SSH is bound to the
  host's loopback address. The tutorial warns never to forward it more
  widely.

## Verification

- **Locally:**
  - `nix flake check ./demo` builds the VM test;
  - `nix build ./demo#vm` succeeds;
  - `nix run ./demo` boots to an automatic console login.

  Inside the VM, confirm by hand: the three agents print their versions,
  `/skills` in Claude Code lists the collection (no model call needed), and
  `~/example` exists.
- **The main repository is unaffected:** `nix flake check`,
  `check_collection.py`, `check-fast` and `nix build .#docs` (with the new
  tutorial page) all pass.
- **`demo.yml` passes** on the pull request with KVM enabled.
- **Sizes:** the VM closure (`nix path-info -Sh ./demo#vm`) and the RAM in
  use are recorded in the tutorial.
